Add owner/admin/operator roles and invitations.

6. Dashboard, reliability, and compliance
27. Simulators can show success after failed requests
The workbench contains success messages that do not consistently check the HTTP result. A simulated call completion is not a real phone call.
Fix: Isolate demos from production data and display actual outcomes.
28. “Hiring” additional employee types only saves configurations
Returns, cart recovery, and wholesale templates do not have corresponding complete execution workflows.
Fix: Label these as unavailable until implemented. Do not sell them as functioning automation.
29. Background processing is not durable
Webhook work uses in-process background tasks. Redis failure falls back to process memory, and processing locks can cause retries to be discarded after a failure.
Fix: Persist webhook receipts before acknowledging them; use durable jobs, processing leases, retries, dead-letter handling, and idempotent side effects.
30. Some settings and privacy claims do not match behavior
Examples:
Currency/timezone/domain fields are accepted, but the profile update only persists the name.
Disconnecting Meta deletes the local integration record but does not implement the claimed full provider-unsubscription/deletion lifecycle.
Some sensitive provider settings are stored in generic settings JSON rather than the encrypted credential fields.
Fix: Persist settings properly, separate and encrypt secrets, implement revocation/deletion workflows, and make privacy statements match reality.
